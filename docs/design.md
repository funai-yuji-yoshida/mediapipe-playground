# MediaPipe お試しアプリ 設計書

作成日：2026-11-17

## 目的
Google MediaPipe で何ができるかを、1つのアプリで確かめて見せる。用途は2つ。
1. **技術調査**：機能を一通り試し、精度・速度・設定による違いを数字で確かめる
2. **講座・商談のデモ**：お客様に「AIでこんなことができる」と、その場で体験してもらう

## 作り方（決定）
- ブラウザで動く **単一HTML**。GitHub Pages で公開する（HTTPSなのでカメラ・マイクが使える）
- MediaPipe Tasks（Web版）を CDN から読み込む
- 映像・音声はブラウザ内で処理し、外部サーバーへは送らない（デモでの説明材料にする）

### 検討した案
| 案 | 長所 | 短所 | 判断 |
|---|---|---|---|
| ブラウザ1枚HTML＋GitHub Pages | URLだけでPC・スマホで動く。準備不要 | 初回にモデルをネットから読み込む | **採用** |
| Python（Streamlit等）でPC実行 | 試せる機能がやや多い | 毎回環境構築が必要で、商談向きでない | 不採用 |
| 公式 MediaPipe Studio をそのまま使う | 作る手間ゼロ | 英語のみ・機能ごとに別ページ・デモ向きでない | 不採用（参考にする） |

## 載せる機能（提案）
| 区分 | 機能 | 入力 | デモでの一言（例） |
|---|---|---|---|
| 顔 | 顔検出 | カメラ／画像 | 来店者数のカウント |
| 顔 | 顔ランドマーク＋表情（52種の表情値） | カメラ／画像 | 表情から満足度・眠気を推定 |
| 手 | 手のランドマーク（21点） | カメラ／画像 | 非接触での操作 |
| 手 | ジェスチャー認識（グー・パー・ピース等7種） | カメラ／画像 | 手袋をしたままの合図入力 |
| 体 | 姿勢推定（33点） | カメラ／画像／動画 | 作業姿勢・腰への負担チェック |
| 物 | 物体検出（80種類） | カメラ／画像／動画 | 在庫・人や車の数え上げ |
| 物 | 画像分類（1000種類） | カメラ／画像 | 写真の自動仕分け |
| 切り抜き | 人物の背景切り抜き | カメラ／画像 | オンライン会議の背景差し替え |
| 切り抜き | クリックした物の切り抜き | 画像 | 商品写真の切り抜き |
| 音 | 音の分類（521種類） | マイク | 異音・アラーム音の検知 |
| 文章 | 言語判定 | テキスト入力 | 問い合わせの言語振り分け |

## 画面
- 左：機能の一覧（区分ごと）
- 中央：映像（入力の上に検出結果を重ねて描画）
- 右：説明パネル
- 上部の切り替えで2つの表示を切り替える
  - **デモ表示**：映像を大きく、日本語の短い説明と「業務でこう使える」の一言
  - **調査表示**：FPS・処理時間（ms）・信頼度、しきい値と検出数の調整、CPU／GPU切り替え、結果の生データ（JSON）
- 入力の切り替え：カメラ／画像ファイル／動画ファイル（機能が対応するもののみ）
- 表示はすべて日本語

## 目標・対象外・失敗の条件
- 目標：URLを開いて30秒以内に、最初の機能をカメラで体験できる
- 目標：PCの Chrome / Edge で動く。スマホは「動けばよい」
- 対象外：文章分類（英語専用のため）、端末内LLM（Gemma。数GBの読み込みが必要）、結果の保存・ログ記録
- 失敗の条件：商談の場で読み込みが止まる・エラーが英語のまま出る

## 制約
- モデルは初回に Google のサーバーから読み込む。回線が不安な場所向けに、後からモデルを同じリポジトリに置ける構造にしておく
- カメラ・マイクの許可はブラウザが求める。拒否された時は日本語で案内を出す

## 実装者に任せる点
- 描画の色・レイアウトの細部
- 各機能で使うモデルの種類（軽量版を既定とし、調査表示で切り替え可能にするのが望ましい）
